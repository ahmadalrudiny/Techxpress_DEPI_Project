01 · المشكلة والفرصة

سوق يحتاج منصة واحدة تجمع البائع والعميل والثقة

التجارة الإلكترونية المحلية تعاني من تشتت البائعين وضعف أدوات المتابعة، بينما يحتاج العميل إلى دفع آمن وتعويض عادل وسهل عند الإلغاء أو الإرجاع.

نقاط الألم

  • بائعون متعددون بلا متجر موحّد أو محفظة أرباح واضحة.
  • دفع تقليدي بلا بوابة آمنة أو تأكيد فوري للعملية.
  • صعوبة تتبع الطلب على مستوى البائع والعميل والإدارة.
  • تعويض الإلغاء والإرجاع غير مرن ولا يمكن إعادة استخدامه.

أهداف المشروع

  • متجر واحد للبائعين المعتمدين مع إدارة كاملة للمنتجات والطلبات.
  • دفع Stripe آمن، وتأكيد دفع لا يُنشئ طلبات مكررة.
  • محفظة أرباح للبائع وعمولة منصة محسوبة على كل بند.
  • نقاط استرداد 1:1 بالدولار تُستخدم في أي شراء لاحق.

التزامات معمارية

  • لا وصول مباشر إلى DbContext أو UoW من Controllers.
  • جميع القراءات غير المتتبعة تستخدم AsNoTracking().
  • كل POST محمي بـ [ValidateAntiForgeryToken].
  • صلاحيات [Authorize(Roles=...)] لكل مسار إداري أو بائع.
  • الأسرار في User Secrets / Azure App Settings فقط.

08 · الأمان والجودة

ثقة تُبنى في كل طبقة من تسجيل الدخول إلى السجل

Identity & Roles

ثلاثة أدوار، حسابات موقوفة لا تسجل الدخول — بكلمة المرور أو Google.

Google OAuth

تسجيل عبر Google من الإعدادات فقط، مع تعطيل واضح عند غياب الإعداد.

حماية الطلبات

Anti-forgery لكل POST، وتحقق ملكية الموارد، ومنع الوصول غير المصرح.

إدارة الأسرار

Stripe وGoogle في User Secrets محليًا وAzure App Settings عند النشر.

Serilog + Middleware

سجلات يومية، Request Logging، وتسجيل الاستثناءات مع الموقع الدقيق.

اختبارات موثوقة

xUnit + Moq + SQLite in-memory، تغطي الدفع والرصيد والعمولة والإرجاع.
